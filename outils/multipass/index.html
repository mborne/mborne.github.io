    Multipass¶

    🤖 Rédaction assistée par IA.

    Multipass est un outil de Canonical qui permet de créer rapidement des VM Ubuntu (mais aussi Debian et Fedora depuis la version 1.17) sous Linux, macOS et Windows.

    Points clés¶

    • Création d'une VM en une commande (multipass launch) à partir d'images officielles.
    • Configuration de la VM au démarrage avec cloud-init (--cloud-init cloud-init.yaml).
    • Même ligne de commande sur Windows, macOS et Linux, avec un hyperviseur natif propre à chaque OS (voir Systèmes supportés).
    • Partage de fichiers entre l'hôte et la VM (multipass mount, multipass transfer).

    Installation¶

    Voir documentation.ubuntu.com - Install Multipass pour l'installation.

    Systèmes supportés¶

    Voir How to set up the driver pour le choix de l'hyperviseur (multipass set local.driver=...) :

    OS Driver par défaut Autres drivers
    Linux qemu aucun (LXD et libvirt dépréciés en 1.16, retirés en 1.172)
    macOS 14+ (Intel ou Apple Silicon) qemu applevz (en preview), virtualbox (Intel uniquement4)
    Windows 10/11 1809+ (Famille, Pro, Entreprise) hcs1 hyperv (déprécié3), virtualbox (déprécié4)

    Principales commandes¶

    Les liens pointent vers la référence de la ligne de commande de la version stable (1.17) :

    Action Commande
    Lister les images disponibles multipass find5
    Créer et démarrer une VM multipass launch -n <nom> --cpus 4 --memory 8G --disk 50G [--cloud-init cloud-init.yaml]
    Lister les VM (état, adresse IP) multipass list
    Afficher le détail d'une VM multipass info <nom>
    Ouvrir un shell dans la VM multipass shell <nom>
    Exécuter une commande dans la VM multipass exec <nom> -- <commande>
    Monter un dossier de l'hôte dans la VM multipass mount /chemin/hote <nom>:/chemin/vm
    Copier un fichier vers la VM multipass transfer fichier.txt <nom>:.
    Arrêter / démarrer la VM multipass stop <nom> / multipass start <nom>
    Supprimer la VM multipass delete <nom> puis multipass purge5
    Afficher / changer le driver multipass get local.driver / multipass set local.driver=<driver>

    Cas d'utilisation¶

    • Création d'une VM de DEV pour VSCode en remote SSH

    Limites¶

    Pas de GPU¶

    Multipass ne permet pas de passer le GPU de l'hôte à la VM (canonical/multipass#2503). Impact : Pas de PyTorch CUDA, pas d'inférence GPU dans la VM (il faudrait utiliser les builds CPU ou WSL2 sous Windows qui supporte CUDA).

    KVM dans la VM selon le driver¶

    La disponibilité de KVM dans la VM dépend de la virtualisation imbriquée (canonical/multipass#3623) :

    • Linux (qemu) : disponible si la virtualisation imbriquée est activée sur l'hôte ;
    • Windows (hyperv) : à activer à la main, VM arrêtée, avec Set-VMProcessor -VMName <vm> -ExposeVirtualizationExtensions $true ; non documenté avec hcs ;
    • macOS (qemu) : non disponible.

    Sur un hôte déjà virtualisé (VDI, VM cloud, runner CI), Multipass ne démarre que si l'hyperviseur sous-jacent expose la virtualisation imbriquée ; lancer en plus une VM dans la VM Multipass (double imbrication) n'est pas réaliste.

    Pour vérifier dans la VM, voir le diagnostic de la fiche KVM - Pré-requis.
