    Lima VM¶

    🤖 Rédaction assistée par IA.

    Lima permet d'exécuter des machines virtuelles Linux locales de manière légère, avec une expérience orientée ligne de commande.

    Points clés¶

    • Création d'une VM en une commande (limactl start) à partir de templates (limactl create --list-templates) : Ubuntu, Debian, Fedora, Alpine...
    • Configuration de la VM en YAML (ressources, montages, provisionnement), avec des valeurs par défaut communes à toutes les VM (voir Personnalisation).
    • Accès SSH transparent (ssh lima-<nom>) grâce à une configuration SSH générée pour chaque VM (voir Accès SSH).
    • Partage de fichiers entre l'hôte et la VM (montage du home de l'hôte en lecture seule par défaut, limactl copy).

    Systèmes supportés¶

    Voir aussi lima-vm.io - VM types

    • Linux : QEMU avec KVM
    • Windows : WSL2 avec virtualisation imbriquée (voir Lima - utilisation sous Windows avec WSL2)
    • MacOS

    Installation¶

    • lima-vm.io - installation
    • lima/install.sh reprend l'approche d'installation à partir du binaire (Linux x86_64 ou aarch64) avec vérification de l'archive (SHA256SUMS). Il affiche la dernière version disponible et installe par défaut une version figée :
    curl -sSL https://mborne.github.io/outils/lima/install.sh | bash
# installation de la dernière version disponible
curl -sSL https://mborne.github.io/outils/lima/install.sh | VERSION=latest bash

    Vérification :

    lima --version
limactl --version
limactl create --list-templates
limactl info

    Principales commandes¶

    Les liens pointent vers la référence de la ligne de commande :

    Action Commande
    Afficher l'aide limactl --help
    Lister les templates disponibles limactl create --list-templates
    Créer une VM (sans la démarrer) limactl create --name <nom> --cpus 4 --memory 8 --disk 50 [template]
    Créer et/ou démarrer une VM limactl start <nom>
    Lister les VM (état, driver, ressources) limactl list
    Ouvrir un shell dans la VM limactl shell <nom> (lima pour la VM default ou $LIMA_INSTANCE)
    Exécuter une commande dans la VM limactl shell <nom> -- <commande>
    Copier un fichier vers la VM limactl copy fichier.txt <nom>:~/ (-r pour un dossier)
    Modifier la configuration d'une VM limactl edit <nom>
    Arrêter / démarrer la VM limactl stop <nom> / limactl start <nom>
    Supprimer la VM limactl delete <nom>

    Sans option, une VM dispose de min(4, nombre de CPU de l'hôte) CPU, de min(4GiB, moitié de la RAM de l'hôte) de mémoire et d'un disque de 100GiB.

    Lors du premier limactl start sans nom, Lima propose de créer la VM default à partir du template default (Ubuntu).

    Montages¶

    Par défaut, le home de l'hôte est monté en lecture seule au même chemin dans la VM (/tmp/lima n'est plus monté depuis la v2.0). Les options de limactl create / limactl start permettent d'ajuster ce comportement :

    Option Effet
    --mount <dossier>[:w] Ajoute un montage (:w pour l'accès en écriture)
    --mount-only <dossier>[:w] Remplace les montages par défaut (ex : --mount-only $HOME/devbox:w)
    --mount-none Supprime tous les montages (isolation de la VM vis-à-vis de l'hôte)
    --mount-writable Rend tous les montages accessibles en écriture

    Le type de montage par défaut est 9p avec qemu et virtiofs avec vz (voir lima-vm.io - Filesystem mounts).

    Accès SSH¶

    Lima génère pour chaque VM un fichier ~/.lima/<nom>/ssh.config (clé SSH dédiée, StrictHostKeyChecking=yes). En ajoutant la ligne suivante dans ~/.ssh/config :

    Include ~/.lima/*/ssh.config

    ... les VM sont accessibles en SSH avec ssh lima-<nom>, ce qui est notamment utile avec VSCode en remote SSH.

    Dans la VM, l'utilisateur porte par défaut le même nom que sur l'hôte et son home est /home/<user>.guest (/home/<user>.linux avant la v2.1).

    Personnalisation¶

    Le fichier ~/.lima/_config/default.yaml permet de personnaliser toutes les VM (voir modèle github.com - lima-vm/lima - templates/default.yaml)

    Support d'un proxy d'entreprise¶

    Il est possible de configurer les variables d'environnement et apt comme suit :

    env:
  HTTP_PROXY: "http://proxy:3128"
  HTTPS_PROXY: "http://proxy:3128"
  NO_PROXY: "localhost,127.0.0.1"
  NODE_USE_ENV_PROXY: '1'

provision:
  - mode: system
    script: |
      #!/bin/sh
      cat > /etc/apt/apt.conf.d/90proxy <<'EOF'
      Acquire::http::Proxy "http://proxy:3128";
      Acquire::https::Proxy "http://proxy:3128";
      EOF

    Cas d'utilisation¶

    • Utilisation sous Windows avec WSL2
    • Création d'une VM de DEV pour VSCode en remote SSH

    Limites¶

    GPU limité au driver krunkit¶

    L'accélération GPU n'est supportée qu'avec le driver krunkit (expérimental, macOS sur Apple Silicon, Vulkan via Venus), voir lima-vm.io - GPU. Impact : pas de GPU sous Linux et Windows (pas de PyTorch CUDA dans la VM).

    KVM dans la VM selon le driver¶

    La virtualisation imbriquée s'active avec nestedVirtualization: true (ou --nested-virt) :

    • Linux (qemu, invité x86_64) : disponible si la virtualisation imbriquée est activée sur l'hôte (paramètre nested de kvm_intel / kvm_amd) ;
    • macOS (vz ou krunkit) : Apple M3 ou plus récent avec macOS 15 ou plus récent.

    Sur un hôte déjà virtualisé (VDI, VM cloud, runner CI, WSL2), Lima ne démarre que si l'hyperviseur sous-jacent expose la virtualisation imbriquée.

    Pour vérifier dans la VM, voir le diagnostic de la fiche KVM - Pré-requis.
